# 制作・審査基準

1. 正解と分類・難易度を決める。難易度は一般成人向けの暫定評価であり、試遊で補正する。
2. 問題と解説の事実を個別に出典と照合する。参考URLを挙げるだけでは確認済みにしない。
3. 同名・類義語・異名の共有・版の相違などの対立候補を確認する。
4. 音声で理解できる独自の文章にする。専門語は問か解説で意味がわかるようにする。
5. 許容表記を確認する。核を欠く短縮や他人のファーストネームを一般ルールで正解にしない。例えばベートーヴェンにはベートーベンを登録できるが、「べん」は登録しない。
   2026-10-31のユーザー指定により、作品名・地名など人物名以外の固有名詞の略称は認めない。「Minecraft／まいんくらふと」はよいが「マイクラ」は不可。「あつまれ どうぶつの森」はよいが「あつ森」は不可。正式な別題・原題と、俗称・略称を混同しない。これは従来の短縮許容より優先する。
6. 作成者以外の人が確認し、審査者・確認日・根拠を記録した問題のみ `approved` にする。

## 原本

`data/questions.jsonl`：利用者向けの8項目。1行1問でIDは固定し、削除後も再利用しない。`タグ`は回答対象種別と内容領域の管理語彙を格納する。

`data/reviews.jsonl`：同一IDに対する版、状態、調査の入口、事実の確認記録、一意性の判断、審査者と日付を保存する。調査の入口は出典確認の証拠ではない。

状態は `candidate`（調査・審査未完了）、`verified`（事実照合済み、人の承認待ち）、`approved`（公開承認済み）、`held`（保留）、`retired`（取り下げ）。事実の確認記録には主張、URLまたは書誌、該当箇所、確認日を残す。

タグの審査状態は審査記録の `tag_status` で管理する。`reviewed` は問題内容を個別に読み、回答対象種別と内容領域のタグを付与済み、`pending` はタグ付与を保留している状態である。単にジャンルやサブジャンルから全件を機械生成したタグは審査済みとしない。

時点により変化する事実は基準日と再確認予定を残す。変動しにくい事実を優先する。難易度1は入門、2は初級、3は中級、4は上級、5は難問。1・2はほとんどの一般成人が知っている水準とし、1は日常の基本、2は広く知られる名称を具体的な手がかりから答えられる問題とする。答え自体が有名でも、決定に必要な手がかりが専門的なら3以上を検討する。文の難解さで難易度を上げず、必要なら設問を改稿する。分野による認知差を考慮し、割当て理由を個別に記録する。試遊前の値を実測値として扱わない。

## 35,000問の配分

既存データを含む総数35,000問を目標とする。7ジャンル各5,000問、各難易度1,000問を配分の目安とする。小分類と正解対象の集中も点検し、言い換えだけの増問はしない。難易度の割当てを件数の都合で変えず、試遊後の校正により配分を調整する。

制作件数、出典照合件数、人による公開承認件数を別々に示す。35,000問の候補ができても、35,000問の照合・公開承認が済んだとは扱わない。
