## 合意した仕様

- ジャンル：アニメ＆ゲーム、文系、理系、生活、雑学、エンタメ＆スポーツ、社会。
- 総数目標：35,000問（既存分を含む）。7ジャンル×5段階の各区分1,000問を配分の目安とし、難易度は内容と試遊に基づいて判断する。初回350問は保持する。
- 問題文は50文字前後を中心に、答えと一緒に読めば未経験者にも意味がわかる表現にする。
- 正解対象を一つに限定する。情報を足す場合は、前半の特徴から後半の決定的な手がかりへ並べる。
- 数や色などの細部を直接答えさせる問題は初回制作に含めない。
- 列順：`ID,ジャンル,サブジャンル,難易度,問,解説,答えjson`。
- `答えjson` は文字列配列。先頭が代表表記、2番目が読み、残りが許容表記。
- システム側でひらがな・カタカナを同一視するため、両方を列挙しない。
- 中黒、空白、全半角の違いは判定側で吸収する。姓だけ、接尾辞なしなどは一意に判定できる場合に限り明示登録する。任意の部分一致や曖昧な短縮は認めない。
- 作品名・地名など人物名以外の固有名詞は、正式な名称で答える。「マイクラ」「あつ森」「ドラクエ」などの俗称・略称や、題名の一部だけの回答は受け付けない。正式な別題・原題と、読みや文字の表記揺れは区別して審査する。

## 品質と保存

問題データと事実確認の状態は分けて管理します。候補は公開済み・裏取り済みを意味しません。Wikipediaは調査の入口とし、公式資料などで問題・解説の各事実と誤答候補を照合します。人の最終審査が終わるまで公開用出力には含めません。詳細は `docs/quality.md` を参照してください。

ユーザー提供の履歴から合意した要件をこの文書に整理しています。履歴原文はリポジトリに含めません。作業を区切るたびにコミット・プッシュし、進捗は `docs/progress.md` に記録します。秘密情報や認証値は保存しません。

## 開発

Python 3.12以上、標準ライブラリのみを使います。追加のAPIキー、データベース、Webサーバーは不要です。

```sh
cd /workspace/Gen_Quiz
python -m unittest discover -s tests -v
python scripts/quiz.py validate
python scripts/quiz.py export --status all --output exports/all.csv
python scripts/quiz.py export --status verified --output exports/verified.csv
```

CSVの `答えjson` はJSON配列の文字列です。出力はUTF-8 BOM付きで、一般的な表計算ソフトでも読み込めます。

```sh
python scripts/quiz.py judge Q000259 'べーとーべん'
# 正解
python scripts/quiz.py export --output exports/approved.csv
# 現時点では承認済み0問なのでヘッダーのみ
```

原本では `答えjson` は配列、CSVではJSON文字列です。例：`["ベートーヴェン", "べーとーゔぇん", "ベートーベン"]`。代表表記がかなの場合も、仕様上2番目には読みを置きます。同じ対象のかな表記をそれ以降へ重複登録しません。

出典の取得版を確認し直す場合は `python scripts/check_sources.py --workers 4` を実行します。Git固定版と公式Web資料の再取得・保存済みSHA-256との一致を調べるだけで、問題の事実照合や公開承認は行いません。
